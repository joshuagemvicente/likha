# Changelog

## Unreleased

- **Provider-only pivot:** removed the `local` provider row — Lisa no longer offers a built-in local-model fallback (Ollama/llama.cpp). Every predefined provider is hosted and requires the user's API key. A `config.json` or `--provider local` reference from an older run now fails with "unknown provider"; re-run the first-run setup to choose a hosted provider. Custom OpenAI-compatible endpoints (`--endpoint`, plain HTTP loopback only) remain available as unverified.

- Added provider-required session routing for Opencode: requests to `opencode-zen` and `opencode-go` carry the stable SQLite session ID in `x-opencode-session` (their API rejects chat completions without it) and every provider request identifies Lisa with `User-Agent: lisa/<version>`.

- Added first-run provider setup in the TUI: launching with no provider configured prompts for a provider, a masked API key (checked against the provider before continuing), and a model chosen from the provider's reported list; the choice is stored in the private state directory (`config.json`/`providers.json`, mode 0600) so later launches skip setup. Flags and environment variables skip and override setup; unconfigured non-interactive invocations fail clearly. See `specs/first-run-setup/`.

- Added `scripts/install.sh`, the public installer for released binaries: `curl -fsSL https://raw.githubusercontent.com/gem/lisa/main/scripts/install.sh | sh` installs the latest release (or a pinned version, `| sh -s -- vX.Y.Z`) for the detected macOS/Linux host into `$HOME/.local/bin` without sudo, after verifying the downloaded archive against the release's SHA-256 manifest. Overrides: `LISA_VERSION`, `LISA_RELEASE_BASE` (self-hosted mirrors; HTTPS required except loopback test hosts), `LISA_RELEASE_API`, `LISA_INSTALL_DIR`. Specified in `specs/curl-install/`; exercised locally against served release artifacts on macOS ARM64 (success, checksum-mismatch, unknown-version, insecure-base, and version-conflict paths). No release has been published, and the published-binary walkthrough remains the release gate.

- Added a predefined accepted provider list with BYOK configuration: `--provider openai|openrouter|bedrock|dialagram|opencode-zen|opencode-go|local` and API keys resolved from `--api-key`, `LISA_API_KEY`, the provider's own `LISA_<NAME>_API_KEY`, or the private state directory (`providers.json`, mode 0600). Connection checks at startup and before each agent run report unreachable endpoints and revoked keys before any prompt is sent; endpoints outside the list run with a visible unverified warning. Opencode Zen and Opencode Go `/models` routes verified OpenAI-shaped publicly; hosted providers still need a live-key probe.
- Made the model name optional: without `--model`/`LISA_MODEL`, Lisa uses the first model a local endpoint reports or the provider's documented default. `lisa --help` now prints the full option, provider, environment-variable, and example reference.
- Added a full-screen, paginated terminal interface with streaming OpenAI-compatible responses, cancellation, and repository-scoped `list_files`, `read_file`, and literal `search_files` tools.
- Added reviewed `edit_file` proposals with a displayed diff, explicit approval or rejection, and stale-edit protection. Added `run_command` reviews showing the exact command and working directory, with output and exit status after approval. Approval requires viewing every review page; rejected actions do not run. Commands are **not sandboxed** and can reach files outside the repository and the network.
- Added private local SQLite sessions associated with a canonical repository path, listing via `--sessions`, resuming via `--resume ID`, and a configurable `LISA_STATE_DIR`. Pending approvals are not saved as permissions.
- Added local versioned macOS/Linux release archive and checksum-generation scripts, a host-target installation smoke script, and installation and manual TUI walkthrough instructions in the README. No release has been published.
- Verified `go test ./...` and `go test -race ./...`; built four local archives, checked their SHA-256 manifest, and installed the macOS ARM64 archive. In its TUI, a local protocol server exercised rejected and approved edits/commands, session resume, interrupted approvals, and SQLite backup restore.

### Verification gaps

- `opencode-go` is live-verified (user session, 2026-09-29: setup flow, connection check, streaming, agent tool usage). `opencode-zen` shares its surface and session header but awaits a live-key turn; OpenAI, OpenRouter, Amazon Bedrock, and Dialagram remain unprobed and must not be described as accepted until each passes the full probe. See `specs/predefined-providers/`. (Local-model verification became moot with the provider-only pivot; the `qwen3:4b` session recorded on 2026-09-29 predates it.)
- Installing and walking through a published binary on every supported host/architecture remains outstanding. Local archive generation and `--version`/`--help` smoke checks do not establish that release gate.
