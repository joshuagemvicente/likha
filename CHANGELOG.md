# Changelog

## Unreleased

- **Official Sign in with ChatGPT replaces the borrowed Codex login** (specs/chatgpt-plus, in progress): selecting ChatGPT in first-run setup or on an unconnected `/providers` row now opens the system browser automatically for OpenAI's documented SIWC authorization — no pasted code, device code, or second launch keypress; a manual URL appears only if the browser launcher fails. Likha registers under its own name (`agent_name_hint=Likha`, stable persisted `ext_agent_host_id`, issued `oaiapp_…` client IDs), verifies the returned ID token's signature/issuer/audience/expiry/nonce against OpenAI's published JWKS, and gates model use on the granted `chatgpt.tokens.use.direct` scope. Saved registrations stay separate per account/workspace (same email allowed), refreshes rotate under a state-directory lock with atomic `0600` persistence, and sign-out attempts remote revocation before clearing tokens while retaining registration and host metadata. Model discovery and inference moved from the private Codex backend to the public `https://api.openai.com/v1`: authenticated `models[]` (visibility `list`, `display_name`, `slug`) and stateless streaming `/v1/responses` with `store:false`, `stream:true`, full input history, and namespaced function tools; only `response.completed` counts as success. `likha --provider chatgpt --login` performs the same browser flow outside the TUI; `--device-login` is now unsupported and explains itself. Legacy Codex tokens require fresh browser sign-in. Plan spend is no longer fabricated as `$0.00`: cost is unknown unless the provider reports a charge (optional credits are an explicit ChatGPT-settings opt-in). Verified: automated checks only — `go build ./...`, `go vet ./...`, `go test ./...`, targeted `-race` runs, and a local end-to-end SIWC fixture (`tests/siwc`) exercising real loopback callbacks, signed RSA/JWKS OIDC validation, locked refresh rotation, account-specific model discovery, and Likha's unchanged two-round tool loop; a live probe with a real Plus/Pro account and browser is still outstanding, so the provider remains pending-probe.

- **Approve always** (specs/approve-always): edit, ask-tier command, and MCP reviews offer a third button, **Approve always** (narrow `[Always]`), gated by the same read-to-end rule as Approve. On an edit it applies every later repository edit in the session without a review; each still shows its diff in the transcript marked `auto-approved`, the status line shows `AUTO-EDIT`, edits are still validated and stale targets still refused, and an oversized root `AGENTS.md` or an `/init` proposal always asks. On a command it replaces **Allow for session** and covers the command's prefix (`go test ./a` covers `go test ./b`; `npm run lint` covers `npm run lint --fix`, not `npm run deploy`); interpreters, wrappers, executors such as `npx`, network tools, and `go run`/`cargo run` stay exact-string, a chained or piped command never matches a prefix, and always-ask or refused commands can never be granted. On MCP, plain **Approve** now runs one call only and **Approve always** trusts the server; MCP trust now also resets on session switch and deletion, not only relaunch. All grants live in memory and end on session switch, session deletion, or relaunch. Verified: automated checks only — cmdpolicy scope and matching table tests, agent tests (prefix grants, danger commands never covered, edit grant skips review but still validates, warnings and `/init` still ask, decline/cancel never grant, `Result.Diff` never reaches model content), MCP once/always/reset tests, 15 TUI tests (bar at 40–80 columns, breakpoints, gating, session reset, `AUTO-EDIT` marker, auto-approved diff rendering), and `go test -race` on agent, cmdpolicy, mcp, tools, and tui. A real-TUI walkthrough is outstanding.

- **Steer now with Ctrl+Enter** (specs/steering-prompts M2, re-specified 2026-10-05): during a run, **Ctrl+Enter** delivers the draft (after any already-queued messages) without waiting for the model to finish. If a model request is in flight, Likha stops only that request and continues the same run with a fresh one; the visible text already written stays in the conversation and its history, followed by `Response interrupted to deliver your message.`, while partial reasoning and half-streamed tool calls are dropped. A steer never interrupts a running tool: it waits for the tool calls to settle (`Steer waits for the running tool`). Enter still queues. Terminals deliver Ctrl+Enter, Shift+Enter, and Ctrl+J as one key, so all three steer during a run and still insert a newline while idle; Alt+Return (single-chord arrival) inserts a newline in a running draft. Providers report usage only in a response's final frame, so a stopped request marks session spend approximate (`~`). This replaces the never-built `Ctrl+Q` send-now design. Verified: automated checks only — agent tests with scripted SSE streams (stop and continue, reasoning-only, partial tool call dropped, steer during a tool waits, run cancel wins, stale signal ignored), a Codex-stream cancellation test, 15 TUI tests including an end-to-end steer against a blocking SSE server with a real session store, and `go test -race` on agent, model, and tui. The live Ghostty key probe and a real-TUI walkthrough are outstanding.

The agent checks the rest with read-only commands, asks only unresolved choices, posts a `plan_update` plan, then runs each step through normal approvals and verifies. The single-question form is unchanged. The main prompt gains "Asking the user" rules: ask when a wrong guess means real rework, otherwise proceed and state the assumption. **Verification:** automated checks only (`go test ./...` green, including an end-to-end questionnaire through a fake provider and `-race` on the plan gate). - **Command approvals** (specs/command-permissions): `run_command` requests are now sorted before Likha asks. Commands such as `rm -rf /`, recursive deletion of the repository, `mkfs`, `dd` onto a device, fork bombs, and `curl … | sh` are refused, and the model is told you can run them yourself. Every command runs without `LIKHA_API_KEY` or any `LIKHA_*_API_KEY` in its environment. Below 56 columns the buttons read `[Approve] [Session]`/`[Trust]` `[Decline]`. - **`web_search` now uses a pluggable search backend instead of Brave alone** (specs/web-tools, specs/tooling-platform phase 5): `tools.json` `web.search.backend` selects exactly one of `brave`, `tavily`, `exa`, or `duckduckgo`. Any other value (or a missing backend, or a malformed `tools.json`) is a visible config error that disables both `web_search` and `web_fetch`. Likha uses one backend at a time and never falls back to another vendor on failure, rate limiting, or misconfiguration. Keys are per provider: `BRAVE_SEARCH_API_KEY`, `TAVILY_API_KEY`, or `EXA_API_KEY` wins over the matching `brave`/`tavily`/`exa` entry in the private 0600 `tool-keys.json`.
