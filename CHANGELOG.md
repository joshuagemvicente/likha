# Changelog

## Unreleased

- **Fixed `/models` identical model ids reading like duplicates** (specs/models-perf): when two configured providers report the same model id (a router proxy like Dialagram re-lists its upstream's models), each colliding row now renders `id · Provider` so both listings read as per-provider entries instead of a glitch; unique ids and the live pair's `(current)` marker keep their labels. Alongside the earlier sticky section header (a clipped window no longer renders models without their section title), a short terminal can no longer show a provider's models unattributed.

- **`/models` lists every configured provider's models, grouped under one section header per provider** (specs/all-models): the dialog fans out over each stored key/sign-in concurrently (5 s bound, active provider's section first, predefined order after), shows non-selectable display-name headers with model ids only on the rows, and filters over model and provider text with a section shown iff one of its rows matches. Enter on the live provider keeps the exact previous apply; Enter on another provider's row moves the session to that provider+model, stores the pair in `config.json`, and names both in one entry. Failed providers contribute no rows (named in a muted note, or the dialog error when nothing lists); unconfigured providers are absent (`/providers` stays the configure path); the signed-in `chatgpt` row contributes its curated list with no network. `/help` and the README now say "every configured provider".
- **Instant cached `/models` open with background refresh** (specs/models-perf): a `/models` open within 5 min of a successful fetch renders the last good list immediately with no spinner and refreshes every configured provider in the background, replacing sections in place in final order; cold or expired opens render sections progressively as they arrive instead of waiting for the slowest provider, Enter applies with ≥1 section present, stragglers contribute no rows and are named in a muted note, and provider-set changes show on the next open. The cache is in-memory only — a restart opens cold. This supersedes the all-models no-cache non-goal by design; grouping, filtering, cursor, and both apply paths are otherwise unchanged.

- **Renamed the repository tools to `glob`, `read`, and `grep` and upgraded their semantics** (formerly `list_files`, `read_file`, `search_files`): `glob` matches file paths by pattern — `*`, `?`, and `[...]` within one path segment, a bare `**` spanning zero or more directories, files only, sorted, capped at 1000 results — replacing the plain directory listing; `grep` searches text files with a real regular expression (Go regexp syntax, per line, case-sensitive unless the pattern uses `(?i)`, capped and budgeted exactly like the old literal search), replacing the literal `search_files`; `read` keeps the 1 MiB UTF-8 read. Absolute patterns, parent traversal, and malformed classes are rejected up front. The old tool names no longer exist; stored sessions resume fine (tool messages are keyed by call ID, not name). Note: the recorded live tool-call probe evidence for hosted providers predates this rename — the rename is a harness-surface change, so the per-provider live probes should be repeated before release claims rest on them.
- **Capped the conversation measure on ultrawide terminals and pinned a no-overflow invariant across every render path** (specs/tui-layout phase 2): conversation content wraps to a content width — the viewport minus two padding columns at every terminal width (the later 120-column cap above 140 terminals was removed so lines reach the right edge) — and resizing re-wraps the transcript immediately. Raw logo lines hard-wrap if ever wider than the viewport (a no-op for the current fixed art), and dialog boxes are measured in display cells instead of UTF-8 bytes, fixing two latent dialog bugs: CJK labels inflated the box, and the `/models` provider column stayed reserved in the width accounting after the too-narrow layout dropped it from the row. New invariant tests pin "no rendered line exceeds the viewport" in display cells per render path — the conversation body (long unbreakable tokens, CJK, control/zero-width runes, widths 40–200), pending reviews, the logo, dialogs, the composer in every style, and the `@`/`/` popups — plus the breakpoint function and the 141→100-column resize re-flow. The audit found the composer and popup paths already correct; no code changes were needed there.
- **Decluttered the TUI header and moved identity into the status bar** (specs/tui-layout phase 1a, FR-12 amended): the top header is gone entirely at ≥56 columns — page 1 opens with the bare ASCII logo (its embedded `Repository:` line removed; the path lives in the status bar's folder segment) and every layout consumer (body height, composer, popups, page math) stays correct with a zero-line header across resizes. On narrower terminals the logo is skipped and one compact line, `Lisa · <repository basename>`, is the only header. The status bar's `Lisa` wordmark moved from the left edge to the bottom-right end of the row (width ≥ 70, first thing dropped under width pressure).
- **Enriched the status bar** (specs/tui-layout phase 1b): the context segment upgrades to `ctx 34% · 68k/200k` (bare `ctx 34%` on the two-row narrow layout); `ctx —` now also renders — never a fabricated percentage — when the model has no publicly documented window, even if usage was measured. The model shows its curated **display name** (`GPT-4o`) instead of the raw slug, with slugs unchanged in `/models`, stored config, and API calls. One bounded `git status --porcelain -b` (3 s, session start plus after each tool result) replaces the separate branch and count readers (`currentBranch`/`gitStatusCounts` deleted) and feeds: branch (compact arrows `↓1↑2` vs upstream, hidden when in sync or absent; short SHA when HEAD is detached), staged/changed counts, and a separate **untracked count**; any git failure silently hides every git segment. A new **environment** segment shows `macOS arm64` / `Linux amd64` from the Go runtime. A new **session-spend** segment accumulates dollars (`$0.42`) from provider-reported cost or a curated per-Mtok price table — ChatGPT subscription models render the known `$0.00`, and models with no documented pricing keep the segment hidden; raw token counts remain in `tokens`.
- **Auto-generated session names** (specs/tui-layout phase 1c): after the first completed turn of a fresh session, one background call to the configured model generates a 2–6-word name (`Fix Parser Bug`) that replaces the derived first-prompt title in the status bar's `session` segment, `/sessions`, resume dialogs, and `--sessions`. Fire-and-forget — it never blocks the next prompt, shows no transcript entry, and a failure or early exit silently keeps the derived title; exactly one generation per session, and resumed sessions never re-generate.
- **Config default change:** `status_line.folder` and `.branch` are now **on by default** (they carry what the header dropped). The two keys migrate to optional booleans in `config.json` — an absent key means on and old configs without them gain the segments; an explicit `"folder": false` / `"branch": false` still disables. All other `status_line` toggles keep their default-off behavior. See `specs/tui-layout/` (spec, tasks, checklist; status "implemented (local) — phases 1–2 done, phase 3 pending"). The real-terminal walkthrough (actual mark placement, narrow-layout glyph widths) is recorded there as the outstanding verification.

- Added **readline-style composer editing** (FR-17, specs/tool-rendering-terminal-keys): a real cursor (Alt+B/Alt+F word motion) with word kills — Ctrl+W / Ctrl+Backspace / Alt+Backspace delete the previous word together with its whitespace run, Ctrl+Delete / Alt+D / Alt+Delete the next word — line kills Ctrl+U (to start) and Ctrl+K (to end) sharing a small kill ring with Ctrl+Y yank (a repeat cycles the last eight kills; an edit ends the cycle), and Ctrl+T transpose. **Alt+Return** (ESC-encoding handled by a 50 ms decay window), **Ctrl+Return / Shift+Return** where the terminal sends them, and **Ctrl+J** insert a newline into the draft; bare Enter still sends, flattening typed and bracketed-paste newlines to spaces. - **Tool activity renders muted** like model reasoning: `tool_start`/`tool_result` transcript entries now use the theme's muted role instead of plain foreground, so machinery reads quieter than assistant content (FR-15 extended to the tool stream).

- Added **`/compact [focus]`**: one summarize model call over the conversation so far preserves the goal, decisions, files changed, next steps, and open questions, then replaces the summarized turns with a single brief (sent as context every later turn), marked in the conversation by a visible "Conversation compacted. Summary of earlier turns:" entry. The compacted session persists and resumes compacted. Optional focus text (`/compact focus on the approval refactor`) steers the summary without being stored as conversation content. Refusals are visible entries and change nothing: no configured model (refused at dispatch, never reaching the network), a pending review, or an empty history ("Nothing to compact yet."). A failed or cancelled summarize (Esc) leaves the history byte-identical with a visible error and allows retry. Manual-only in v1 — no automatic compaction near the context limit, because Lisa has no token counting. See `specs/conversation-compaction/`.
- Added a **slash-command autocomplete popup**: typing `/` at the start of the prompt opens a popup of the reserved commands with one-line descriptions — type-to-filter (case-insensitive substring), ↑/↓ to move, Tab to complete, and Enter to complete unless the draft is already an exact command name (then it sends, so a fully typed `/compact` plus Enter dispatches while `/comp` plus Enter completes). It closes the moment a space is typed and never coexists with the `@` file popup; both popups now show the hint row `↑/↓ select  Tab complete  Esc dismiss`. `/help` lists `/compact [focus]`.
- Replaced the discrete page model with **continuous, browser-like scrolling**: the mouse wheel moves the view a few lines per notch instead of paging, PgUp/PgDn step one viewport, Home/End jump to the very top and the newest content, and the status line keeps a page-position indicator. The view follows new streaming content while at the bottom and stays anchored when scrolled up, like a chat. The approval gate now requires scrolling to the end of the pending proposal instead of viewing every page (spec FR-14 amended).
- Added a **one-column scrollbar** on the transcript's right edge when content overflows the viewport: a dim track with a proportional, theme-colored thumb, clickable and draggable (the thumb jumps to the pointer's position; dragging away from the bottom unhooks the pinned view).
- Added a **blinking block caret** in the composer: solid while typing, blinking (530 ms cycle) when idle, hidden while a run is active or an approval is pending; with an empty draft the block renders before the placeholder. (Spec FR-17 amended.)

- Added the Phase B status line beneath the composer: active provider/model, honest `ctx —` until context usage is measured, and fixed-priority page/working/review controls in one wide row or two narrow rows. `config.json` can enable `status_line.folder`, `.branch`, `.session`, and `.version` individually (all off by default); the Git branch is read without a dirty-file scan. The existing ChatGPT rate-window summary remains separate from context usage. No cost or token estimate is shown without Phase C data.

- Added the Phase C measured segments and Phase D branding to the status line and header. Usage from the provider's last response is captured per run (`prompt_tokens`/`completion_tokens`, `input`/`output` aliases accepted) and drives `ctx <n>%` of the model's documented context window (warning past 80%; `ctx —` stays unmeasured or when no publicly documented window exists, and it never replaces the separate ChatGPT rate-window summary); `tokens <sum>`, `minutes <N>m`, `changes`, `staged`, condensed `mcp <running>/<configured>` (hidden with no servers), and `update → vX` join the optional toggles under `status_line`, keeping the whole catalog off by default. `changes`/`staged` run a bounded (3 s) `git status --porcelain` at session start and after tool results. The update check (`internal/update`) is throttled to once per 24 h per state directory (`update_check.json`, 0600), honors `LISA_UPDATE_API` and `LISA_UPDATE_CHECK=0`, is silent on every failure, and never notifies development builds. The `Lisa` wordmark leads the wide row only at width ≥ 70 and retires first under width pressure. The persistent five-row logo header is retired for a compact three-line header; fresh sessions render the ASCII logo as the first transcript block (skipped below 56 columns, never persisted or redrawn on resume). No pricing data exists, so no cost is shown anywhere.

- Added `@` file references: typing `@` in the prompt opens a file popup over the repository (background index walk, hidden directories skipped, type-to-filter, ↑/↓, Enter/Tab complete, Esc closes; with no matches Enter still submits), and `@path` tokens in a submitted prompt inline the referenced files' content into the user message the model receives (up to 16 files / 64 KiB per turn, repository-confinement enforced). Unresolvable references stay literal; expansion is per-turn and not persisted in sessions.
- Extended `@` references with **folders** and ignore rules: the popup lists directories (trailing `/`) alongside files, a folder reference (`@src` or `@src/`) inlines the folder's tree listing (capped at 200 entries with a truncation marker), and the shared confined `Repository.Tree` walk (used by both the popup and expansion) excludes `node_modules` at any depth, hidden directories, symlinks, and everything matched by the repository's `.gitignore` files — root and per-directory rules, deeper rules winning.

- Added four live composer styles: `minimal` (default), `bordered`, `borderless`, and `chatter`. Ctrl+G while idle opens the style dialog; the selected shape is stored under `composer.style` in `config.json`. Drafts stay visible while the transcript pages, the footer's three hint rows become one state-aware row, and bordered/chatter degrade to minimal at 40 columns. Approval paging and keys are unchanged.

- Added the `chatgpt` provider ("ChatGPT (Plus/Pro)", base `https://chatgpt.com/backend-api/codex`): keyless access to your ChatGPT Plus/Pro subscription through OpenAI's Codex backend via OAuth 2 — OpenAI's public Codex CLI PKCE client, loopback callback on port 1455. First-run setup shows a "Press Enter to open the browser" login stage and then offers the curated model list (default `gpt-5.5`; the backend has no model-list route); no API key is ever entered. Headless setups run `lisa --provider chatgpt --device-login`: it prints the verification URL and code, waits for approval without needing a TTY or repository, and stores the login. Requests go to the OpenAI Responses wire at `<base>/responses` with `ChatGPT-Account-Id` and per-conversation `session-id` headers; access tokens refresh automatically (concurrent turns share one in-flight refresh) and the fresh token set is re-persisted, and a failed refresh reports "chatgpt login expired; sign in again". The main-view footer shows the backend's five-hour rate-window usage when the response carries `x-codex-primary-*` headers. Credential storage moves to schema v2 of `providers.json` (typed `"api"`/`"oauth"` entries, mode 0600), with the legacy plain-key map migrated on read. Privacy and limits: conversation content goes to OpenAI's ChatGPT consumer backend (the browser login screen shows OpenAI's public Codex CLI client), using a subscription through a third-party harness is subject to OpenAI's consumer terms, the five-hour/7-day plan usage windows apply, and there is no per-token cost because your plan pays. The provider ships pending a live probe — implemented and exercised against local test fixtures, but not yet run against a real ChatGPT Plus account, so it is not live-verified.

- Added `/providers`: in-session provider switching via a selection dialog over all predefined providers — ↑/↓ navigate, Enter selects, and typing filters rows case-insensitively (that query filtering now applies to all selection dialogs: `/providers`, `/models`, `/sessions`, `/themes`; Esc clears the filter, then closes). Rows show a configured check or a "not configured" marker; selecting a not-configured provider prompts for its API key inline, stored only after the connection check passes. Switching is **session-only**: the live client changes but `config.json` is untouched — first-run setup remains the way to change the stored default. `/providers <n-or-name>` applies directly without the dialog. The typed `/model <n-or-id>` command is removed; `/model …` is now an unknown command (draft restored, never sent to the model), and model selection happens only through the `/models` dialog. See `specs/slash-commands/providers.md`.
- Added selection dialogs for `/models` and `/sessions`, generalizing the `/themes` dialog: a bare `/models` fetches the provider's list into a centered dialog with the cursor on the live model, and a bare `/sessions` lists saved sessions newest-first. Enter applies the highlighted selection — a model switch now also stores provider+model in `config.json` for future runs, and a session resume happens in place — while Esc discards. The surroundings of each dialog are dimmed (`\x1b[2m` faint); the dialog itself renders at full intensity. The numbered forms (`/model <n>`, `/sessions <n>`) and `/themes <n-or-name>` keep working.
- Fixed dialog rendering: styled dialog rows no longer re-run width fitting, so theme escape sequences no longer leak as visible `\u001B[…m` text beside the cursor, title, or hints, and the rows a dialog spans keep their dimmed content to the left and right of the box instead of collapsing into a full-width solid band. Model-selection rows now show the provider's name right-aligned on the same row (model left, provider right); on terminals too narrow to fit both, the provider column is dropped.
- Fixed a crash when reopening a dialog while its list was still loading (`/models` → Esc → `/models`): the loading view resolved query matches against the stale previous list and panicked with index-out-of-range. The item list is now dropped when a dialog closes, loading renders a placeholder row without match resolution, a late result from an earlier open refreshes the open dialog instead of dumping text behind it, and Enter guards its index against a list that shrank between keypress and confirm (applies to every dialog kind).

- Added MCP (Model Context Protocol) server support: configure stdio servers in `mcp.json` in the private state directory (Claude-Desktop shape); their tools join the agent loop through the existing approval flow with **trust-on-first-use per server** (session-scoped — resets on relaunch). `/mcp` lists servers, state, and tools; a crashed server surfaces as a clear failure and stays dead until relaunch; servers are killed on exit. See `specs/mcp-support/`.

- Added color themes: twenty-two families (`default`, `catppuccin`, `habamax`, `gruvbox`, `tokyonight`, `nord`, `dracula`, `solarized`, `rose-pine`, `kanagawa`, `everforest`, `one-dark`, `ayu`, `flexoki`, `oxocarbon`, `night-owl`, `github`, `monokai`, `material`, `nightfox`, `iceberg`, `horizon`) that adapt to a detected light/dark terminal. Choose via the first-run setup theme stage, the `/themes` selection dialog (↑/↓ to highlight, Enter applies and stores in `config.json`, Esc discards), or `--theme`/`LISA_THEME`. See `specs/themes/`.
- Added Nerd Font support behind `--nerd-fonts`/`LISA_NERD=1`: status and review markers become icon glyphs. Strictly opt-in — plain-ASCII output is unchanged without it.
- Added muted rendering for thinking-model reasoning: streamed `reasoning`/`reasoning_content` deltas appear as a muted "Reasoning" entry in the theme's subdued color, close when real content arrives, and are never sent back to the provider.

- Added full-session scrolling to the paged view: PgUp/PgDn (and the mouse wheel) walk from the very top of the session to the last chat with nothing clipped or unreachable; **Home** jumps straight to the top, **End** jumps back to the newest content.

- Added slash commands in the prompt input: `/sessions` (list, or resume in place with a number), `/models` (list the provider's models), `/model <n-or-id>` (switch the model for future turns, live only), `/quit`, and `/help`. Reserved commands act on the application and are never sent to the model; unknown commands show an error and restore the draft; `//` sends a literal slash. See `specs/slash-commands/`.

- **Provider-only pivot:** removed the `local` provider row — Lisa no longer offers a built-in local-model fallback (Ollama/llama.cpp). Every predefined provider is hosted and requires the user's API key. A `config.json` or `--provider local` reference from an older run now fails with "unknown provider"; re-run the first-run setup to choose a hosted provider. Custom OpenAI-compatible endpoints (`--endpoint`, plain HTTP loopback only) remain available as unverified.

- Added provider-required session routing for Opencode: requests to `opencode-zen` and `opencode-go` carry the stable SQLite session ID in `x-opencode-session` (their API rejects chat completions without it) and every provider request identifies Lisa with `User-Agent: lisa/<version>`.

- Added first-run provider setup in the TUI: launching with no provider configured prompts for a provider, a masked API key (checked against the provider before continuing), and a model chosen from the provider's reported list; the choice is stored in the private state directory (`config.json`/`providers.json`, mode 0600) so later launches skip setup. Flags and environment variables skip and override setup; unconfigured non-interactive invocations fail clearly. See `specs/first-run-setup/`.

- Added `scripts/install.sh`, the public installer for released binaries: `curl -fsSL https://raw.githubusercontent.com/gem/lisa/main/scripts/install.sh | sh` installs the latest release (or a pinned version, `| sh -s -- vX.Y.Z`) for the detected macOS/Linux host into `$HOME/.local/bin` without sudo, after verifying the downloaded archive against the release's SHA-256 manifest. Overrides: `LISA_VERSION`, `LISA_RELEASE_BASE` (self-hosted mirrors; HTTPS required except loopback test hosts), `LISA_RELEASE_API`, `LISA_INSTALL_DIR`. Specified in `specs/curl-install/`; exercised locally against served release artifacts on macOS ARM64 (success, checksum-mismatch, unknown-version, insecure-base, and version-conflict paths). No release has been published, and the published-binary walkthrough remains the release gate.

- Added a predefined accepted provider list with BYOK configuration: `--provider openai|openrouter|bedrock|dialagram|opencode-zen|opencode-go|local` and API keys resolved from `--api-key`, `LISA_API_KEY`, the provider's own `LISA_<NAME>_API_KEY`, or the private state directory (`providers.json`, mode 0600). Connection checks at startup and before each agent run report unreachable endpoints and revoked keys before any prompt is sent; endpoints outside the list run with a visible unverified warning. Opencode Zen and Opencode Go `/models` routes verified OpenAI-shaped publicly; hosted providers still need a live-key probe.
- Made the model name optional: without `--model`/`LISA_MODEL`, Lisa uses the first model a local endpoint reports or the provider's documented default. `lisa --help` now prints the full option, provider, environment-variable, and example reference.
- Added a full-screen, paginated terminal interface with streaming OpenAI-compatible responses, cancellation, and repository-scoped `list_files`, `read_file`, and literal `search_files` tools.
- Added reviewed `edit_file` proposals with a displayed diff, explicit approval or rejection, and stale-edit protection. Added `run_command` reviews showing the exact command and working directory, with output and exit status after approval. Approval requires viewing every review page; rejected actions do not run. Commands are **not sandboxed** and can reach files outside the repository and the network.
- Added private local SQLite sessions associated with a canonical repository path, listing via `--sessions`, resuming via `--resume ID`, and a configurable `LISA_STATE_DIR`. Pending approvals are not saved as permissions.
- Added local versioned macOS/Linux release archive and checksum-generation scripts, a host-target installation smoke script, and installation and manual TUI walkthrough instructions in the README. No release has been published.
- Verified `go test ./...` and `go test -race ./...`; built four local archives, checked their SHA-256 manifest, and installed the macOS ARM64 archive. In its TUI, a local protocol server exercised rejected and approved edits/commands, session resume, interrupted approvals, and SQLite backup restore.
