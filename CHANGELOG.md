# Changelog

## Unreleased

- **Live transcript surfaces: diffs, task items, reasoning, turn footers** (specs/transcript-redesign, slice 3): an applied `edit`/`edit_file` item now states its change (`Updated a.go with 2 additions and 1 removal`, `Updated 3 files with …`, `Created b.go (3 lines)`) and shows up to 10 numbered `+`/`-` lines of the diff you reviewed on the diff-add/remove tints (signs stay without color), then `… +N lines (ctrl+o to expand)` and the other files of a multi-file edit; a file-creating `edit_file` reads `Create(path)`. Declined, failed, and cancelled edits never show a diff. The reviewed diff is saved in a new optional `diff` field on the session's tool record, so it survives resume; records saved earlier rebuild their lines from the edit arguments, without line numbers. An explore `task` item now carries its subagent's live activity on its `⎿` line (`Queued`, `Read path`, `Waiting for 2 subtasks`, with a blinking dot), then settles to `Done · N tool uses · wait Xs · active Ys` or `Failed: reason` / `Cancelled` / `Limited: …` / `Interrupted`; the transcript no longer writes `Agent:` lines (older ones still show as `ℹ` notices, and `/agents` keeps the full tree). Reasoning streams as `✻ Thinking…` with exactly its last three lines in muted italics, then collapses to `✻ Thought for Ns` (`<1s` for short blocks, `Thought` when no duration was recorded); Tab focuses collapsed markers along with tool items, and Enter expands or collapses one inline, its full text rendered as Markdown in muted italics (expansion is per view and never saved). Reasoning after a tool call now opens a new block below the tool instead of growing the one above it, and a new block no longer starts with the previous round's text. Every finished turn (done, cancelled, or failed; never `/compact`) ends with a muted footer `✻ model · duration · N tools`, plus `· cancelled` when cancelled, dropping segments right to left on narrow terminals; `N tools` counts the turn's tool items even when a provider reuses call IDs across rounds. The footer is saved as a `Turn` transcript entry whose payload also holds each reasoning block's duration, so footers and `Thought for Ns` markers reappear on resume; it is never sent to the model. Checks pass; the interactive walkthrough is pending.

- **Markdown in assistant text** (specs/transcript-redesign, slice 2): assistant answers, the streaming one included, render as CommonMark with GFM tables and strikethrough instead of raw `##`, `**`, and backticks: headings in bold `Title` (markers hidden, `#`/`##` underlined), bold/italic/strikethrough, `inline code` in `Accent` on `BgCode`, `•`/`1.` lists (nested lists indented two cells per level, numbers right-aligned), `│` quotes in `Muted`, links with ` (url)` in `Muted`, `─` rules, `[image: alt]`, aligned tables (plain pipe text when too wide), and raw HTML as literal text. Fenced and indented code renders as a `BgCode` panel across the text column, never word-wrapped; a fence naming a known language is highlighted with colors derived from the active theme (keywords `Accent`, strings `Warning`, comments italic `Muted`, the rest `Normal`; `default` uses the terminal's 16 ANSI colors), and unknown languages stay plain. Unclosed fences render as open panels while streaming. Content is escaped before layout, so no escape sequence from model text reaches the terminal; inline color swatches keep working in prose but not in code panels; `--ascii` switches markdown glyphs to `-`, `|`, `+`. Rendered rows are cached per entry, keyed by text, width, theme styles, and glyph set, so only changed entries (such as the streaming answer) re-render. Reasoning and notices stay plain. New dependencies: `github.com/yuin/goldmark` v1.8.6 (MIT) for parsing and `github.com/alecthomas/chroma/v2` v2.24.1 (MIT) for tokenizing, which brings `github.com/dlclark/regexp2` v1.12.0 (MIT); all pure Go. Checks pass; the interactive walkthrough is pending.
- **Transcript blocks replace role labels** (specs/transcript-redesign, slice 1): rows no longer start with `You:`, `Assistant:`, `Tool:`, `Error:`, or `Likha:`. Each block opens with a glyph in a two-cell gutter (`>` your prompt, `⏺` assistant text and tool calls, `✗` errors, `ℹ` notices, `✻` reasoning), and prose wraps at word boundaries with hanging indents. Only your prompts carry a background: a full-width user band with a padding row above and below, now also in the `default` theme as a faint neutral tint; assistant text and tools sit on the base canvas. Each tool call is one item from `tool_start` to its result: a `⏺ Name(args)` header with a status dot (blinking while it runs, then the theme's success or error color), a `⎿` line that states the outcome in words, and up to three preview lines (none for grep/glob) with `… +N lines (ctrl+o to expand)`; Tab stops once per call and Enter/Ctrl+O open the unchanged inspector. New sessions store one entry per call, with the record started at `tool_start` and updated by call id; older sessions load with their request/result pairs merged into one item. The composer defaults to a new `rounded` style (a rounded box with a `> ` prompt, `minimal` at 40 columns); saved styles are kept. `--ascii` / `LIKHA_ASCII=1` switches block glyphs and composer edges to plain ASCII. New derived theme roles (`Accent`, `Success`, `BgCode`, `BgDiffAdd`, `BgDiffRemove`) pass the contrast gate in every family; markdown, diffs, live subagent lines, reasoning collapse, and the turn footer come in later slices. Checks pass; the interactive walkthrough is pending.

- **Web search needs no key by default:** with `web.search.enabled: true` and no `backend`, `web_search` uses keyless DuckDuckGo (previously a config error). Brave, Tavily, and Exa remain opt-in by naming them; a named keyed backend without its key stays unavailable and never falls back. The default path was live-checked on 2026-10-04 (three ranked results through the real adapter); the consent dialog walkthrough is pending.

- **Streamed tool calls without an `index` are accepted:** some OpenAI-compatible gateways and routers (seen on Dialagram's `nexum-router`) omit the per-fragment `index`, which failed the turn with "invalid indexed function tool-call fragment". A fragment without an index now opens a new call when it carries a new call id and otherwise continues the latest call; ids or names repeated on every chunk are no longer doubled. Fragments that have neither an index nor an id, or a non-`function` type, are still rejected, and the error now names which rule the provider broke. Not yet live-verified against the router.

Deleting removes the session row together with its plan, task, and journal rows, and removes the session's private tool-output directory when that cleanup succeeds; if cleanup fails, the session is still deleted and the leftover output is reported as an error. Deletion is refused while a run or review is active, and deleting the current session continues in a fresh one. Checks pass; the interactive walkthrough is pending.

- **`web_search` now uses a pluggable search backend instead of Brave alone** (specs/web-tools, specs/tooling-platform phase 5): `tools.json` `web.search.backend` selects exactly one of `brave`, `tavily`, `exa`, or `duckduckgo`. Any other value (or a missing backend, or a malformed `tools.json`) is a visible config error that disables both `web_search` and `web_fetch`. Likha uses one backend at a time and never falls back to another vendor on failure, rate limiting, or misconfiguration. Keys are per provider: `BRAVE_SEARCH_API_KEY`, `TAVILY_API_KEY`, or `EXA_API_KEY` wins over the matching `brave`/`tavily`/`exa` entry in the private 0600 `tool-keys.json`. Only the configured backend's key is read, and a keyed backend without a key leaves `web_search` unavailable: `/tools` shows the generic reason "The web search backend is not configured.", and the specific message (no `<backend>` key is configured; set `<ENV>`…) appears as a transcript entry when a run starts. DuckDuckGo needs no key. Every backend returns the same bounded result shape, and snippets are never invented. Consent copy is written per provider: Brave keeps its 90-day default query-retention notice; Tavily and Exa say the provider receives the query and request metadata, with retention set by that provider's privacy policy (no invented numbers); DuckDuckGo says it uses the unofficial `html.duckduckgo.com` HTML endpoint, not a sanctioned API, so its markup can change and automated use can be blocked or rate-limited at any time. By design, changing the backend clears the grant: any change to the loaded web config clears every web grant in the conversation, taking effect at the next run start, so switching back to a previous backend asks again; a backend switch in a live session has not been verified. **Verification:** DuckDuckGo is live-verified through a headless call to the real adapter (not a TUI run): two real searches on 2026-10-04 returned ranked results with real URLs, snippets, and unwrapped redirect links. Its fragility notice still applies: a block can surface as a redirect, a rate limit (HTTP 429), or an HTTP status error, and a markup change or empty 200 response surfaces as a named no-parsable-results error (that last path was validated structurally only). For Brave, Tavily, and Exa, the bad-key paths were live-verified on 2026-10-04 (each reports the key as rejected); the successful-search path stays unverified until a probe with a real key is recorded. **Fixes found by those probes:** the Exa adapter sent its key in a misspelled `x-api-1` header and now sends `x-api-key` (bad keys now return 401, key rejected), and Brave's HTTP 422 `SUBSCRIPTION_TOKEN_INVALID` response is now reported as a rejected credential.

- **Type while a run is active; press Enter to queue a steering prompt** (specs/steering-prompts): the composer stays live during a run — typing, paste, kills, word motion, newline chords, and the `@`/`/` popups work, with the caret visible. If a run ends with messages still queued (cancellation, error, or a finished compaction), they are held — nothing auto-starts, Enter on an empty draft sends the whole held batch, and a bare Esc clears it; delivered steers open a fresh assistant bubble and steer deliveries are never dropped (terminal reconciliation), so a queued prompt is delivered exactly once; queue contents are never persisted and never replayed on resume. Reserved `/` commands are refused with a visible message (`//` still queues literal text), and the status line names the queued count (`2 queued`, or `2Q` on the narrow layout).
