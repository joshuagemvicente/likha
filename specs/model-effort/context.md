# Context: Model effort

Code, tests and docs this feature touches, with the facts that shaped the
spec. All decisions live in [spec.md](spec.md); sources in
[research.md](research.md).

## Wire paths

- Every API-key provider, including `claude` (`https://api.anthropic.com/v1`)
  and `gemini` (`…/v1beta/openai`), goes through OpenAI-compatible
  `/chat/completions`. Only `chatgpt` (Sign in with ChatGPT) uses the
  Responses API.
- `internal/model/client.go`
  - `Client.stream` builds the chat-completions body as an anonymous struct
    (`model`, `messages`, `tools`, `stream`, `stream_options`). It has no
    effort field. The `attempt` loop's only retry drops `stream_options`
    (`streamUsageOptionRejected`).
  - `streamChunk.Delta.Content` is `*string`. Mistral's chunk-list content at
    `high` would fail to decode (see "Known gaps").
  - `ModelDetails` and `decodeModelDetails` parse `id` and context-window
    fields only. OpenRouter's `reasoning.supported_efforts` and
    `default_effort` would be added here.
- `internal/model/codex.go`
  - `codexRequest` and `BuildCodexRequest` build the Responses body. Its doc
    comment promises that unsupported request parameters are never sent. A
    `reasoning: {effort}` field must update that comment and be probed.
- `internal/model/fork.go`: `Fork` copies endpoint, model, key, session
  identity and OAuth session. It must also copy the effort so explore and
  profile children inherit it (decision 9).
- Callers of `StreamUsage` and `Stream`:
  - `internal/agent/turn_execution.go`: main turn, carries effort.
  - `internal/agent/explore_loop.go`, `profile_runner.go`: forked children,
    carry effort.
  - `internal/agent/compaction.go`, `sessionname.go`: use the session client
    directly and must send no effort.
- `internal/model/provider.go`: the `Providers` table. A per-row effort wire
  kind goes here; the zero value means the provider cannot carry effort.

## Catalog

- `internal/model/catalog/gen/main.go`:
  - `upstreamModel` reads `reasoning` but not `reasoning_options`.
  - `overrideModel` is the hand-checked correction layer; every entry cites
    `ref` and `verified`.
- `internal/model/catalog/catalog.go`: `Model` has `Reasoning bool`. An
  effort list joins it.
- `models.json` is generated by `go generate ./internal/model/catalog` and is
  never edited by hand (AGENTS.md).
- First override candidates:
  - Gemini 2.5 rows: budget-only upstream, but Google documents the
    low/medium/high mapping of `reasoning_effort`.
  - `chatgpt` rows: curated, with no upstream levels.

## TUI

- `internal/tui/dialog.go`
  - `dialogState` and `confirmDialog`: Enter on a `/models` row calls
    `applyModelRow` immediately. The effort step becomes a sub-state of the
    models dialog, like the sessions dialog's `deleteConfirm` view.
  - `handleCommand` and `commandHelp`: `/effort` is added here.
- `internal/tui/commandcomplete.go`: the `/` autocomplete command list.
- `internal/tui/models_all.go`
  - `modelsRow` (provider, model, context window, display name).
  - `applyModelRow` refuses during a run or pending review, then calls
    `applyModel` (live provider) or `activateModelClient` (switch).
- `internal/tui/tui.go`: `applyModel` writes `cfg.Model` and the
  "Model switched to …" entry.
- `internal/tui/status_line.go`: the model segment (`modelName` around line
  365) and the narrow-width fitting that shortens it.
- `internal/tui/setup.go`: first-run setup has its own model list and does
  not go through `dialogModels`. No change is needed there (decision 4).

## Config

- `internal/providers/config.go`: `StoredProviderConfig` and
  `LoadStoredConfig`/`SaveStoredConfig`. The `ContextWindows` field
  (`map[string]map[string]int64`, provider → model) is the shape to copy for
  stored levels.
- `internal/app/run.go`: the `--model` flag (`LIKHA_MODEL`). The stored level
  applies after the model is resolved; there is no effort flag.

## Provider support matrix

No provider can carry effort until a live probe passes. Probes are run by
the user. Each probe sends one tool-bearing request at each published level
of one model and records accepted, rejected or ignored.

| gemini | `reasoning_effort` | pending-probe | Gemini 3 thought signatures (Known gaps) |
| xai | `reasoning_effort` | pending-probe | silently downgrades unsupported values |
| deepseek | `reasoning_effort` | pending-probe | `reasoning_content` echo (Known gaps) |
| groq | `reasoning_effort` | pending-probe | |

## Known gaps (not in this feature)

- **Reasoning echo.** DeepSeek (thinking on by default) requires
  `reasoning_content` to be passed back when tools are present, and Gemini 3
  requires thought signatures on tool calls. Likha never sends reasoning back
  (FR-15). These failures can happen today at default effort, independent of
  this feature. They need their own spec.
- **Mistral chunk content.** `message.content` as a list of chunks fails
  Likha's string decoder.
- **Native Claude client.** Needed for Claude effort, visible thinking and
  prompt caching.
