# Hosted provider candidates

Research date: 2026-10-02. Likha expects the same base to serve `POST {base}/chat/completions` and `GET {base}/models`; its model-list parser reads OpenAI-shaped `data[].id`.

## Shortlist

**Registered pending-probe:** Groq, xAI, Together AI, Mistral AI, and Cerebras. Their docs support Likha's base-route pattern; Together and Mistral have model-list schema/example discrepancies, so Likha's parser accepts both the OpenAI `data[]` envelope and a top-level model array. No provider has passed a live admission probe here. DeepSeek, Gemini, and Fireworks remain deferred for the integration gates below.

## What each provider needs before Likha can add it

Likha’s current client appends `/chat/completions` and `/models` to one validated base; hosted HTTPS bases must have a non-root path ([client routing/validator](../../internal/model/client.go)). Likha’s key-slot convention is `LIKHA_<CANONICAL_NAME>_API_KEY` ([feature role](role.md)); providers do not define Likha’s environment-variable names. **For every candidate below, no admission probe has been run.** Before marking a provider accepted, the existing gate still requires streamed text, a structured tool call plus tool-result roundtrip, mid-stream cancellation, and a revoked/wrong-key check; docs or a successful model-list request do not satisfy these ([admission gate](../predefined-providers/spec.md)). Keep `DefaultModel: ""` until a successful probe identifies the model to pin ([feature decision](spec.md)).

- **Groq — ready for real probe.** Auth: Bearer API key confirmed; Likha slot `LIKHA_GROQ_API_KEY`. Validator/routes: no change indicated; current client can append both suffixes to this path base. Evidence: chat POST ([compatibility](https://console.groq.com/docs/openai)); exact GET `/models` URL and Bearer example ([models](https://console.groq.com/docs/models)). Probe: all four admission checks above remain outstanding. Default: blank pending probe.
- **xAI — ready for real probe.** Auth: Bearer API key confirmed; slot `LIKHA_XAI_API_KEY`. Validator/routes: no change indicated. Evidence: POST example uses this base ([Chat Completions](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions)); GET `/v1/models` documents `data[].id` ([Models](https://docs.x.ai/developers/rest-api-reference/inference/models)). Probe: all four outstanding. Default: blank pending probe; Chat Completions is documented as legacy.
- **Together AI — registered pending-probe.** Auth: Bearer API key; slot `LIKHA_TOGETHER_API_KEY`. Base: current official docs use `api.together.ai`. Parser: accepts either documented array/envelope shape. Probe: raw response shape and a chat-capable model, then the full gate. Default: blank.
- **Mistral AI — registered pending-probe.** Auth: Bearer API key; slot `LIKHA_MISTRAL_API_KEY`. Parser: accepts the model endpoint's schema/example variants. Probe: raw response shape and tool-capable model, then the full gate. Default: blank.
- **Cerebras — registered pending-probe.** Auth: Bearer API key; slot `LIKHA_CEREBRAS_API_KEY`. Routes: no client route changes indicated. Probe: full gate, including compaction's developer-role message with a compatible model. Default: blank.

Evidence: [NVIDIA API catalog](https://build.nvidia.com/llms.txt). Probe: after route resolution, all four admission checks. Default: blank pending probe.

## Probe boundary

“Ready for real probe” means the two endpoint paths and model-list ID shape are documented well enough to justify a credentialed compatibility test. It does **not** mean a live endpoint was called, nor that streaming, tool calls, cancellation, revoked-key handling, or other Likha admission checks pass. “Needs verification” means the endpoint pair or Likha URL handling is not established by these docs; none of those cases is called incompatible based on absence of documentation alone.
